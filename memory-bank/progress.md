## What Works / Exists
- Party membership is an ephemeral Unity dedicated-server system: groups and pending invitations live only in static process memory and reset with the server. Only accepted, online friends can be invited from the Friend List; only the party leader can extend an existing group. Accept/decline, leave, disconnect cleanup, and leader succession synchronize targeted snapshots to clients. The prefab-backed left-side Party UI lists name, live HP, Main level, and leader status and exposes invitation decisions plus leaving. Friend List rows include the calculated Main level. Shared quest and experience behavior is not part of this foundation yet.
- Friend List is character-scoped and persistent. A unique canonical relationship row represents either a pending invitation or an accepted friendship; only the invitation recipient can accept or decline it. Server-player-session endpoints list friends/incoming/outgoing invitations, invite by unique character name, respond, remove, and authorize a whisper. Online state comes only from active redeemed player sessions belonging to the authenticated dedicated server's single active game session. The Unity dedicated server owns every friend RPC, derives the sender from authenticated server state, reauthorizes accepted friendship before each targeted whisper, rate-limits and caps messages at 200 characters, and never sends whisper text to the API. The owner client supports `/w CharacterName message` and row-based whisper initiation. `UIScene` contains a `407.6577 x 407.6577` upper-right panel matching Character's rounded 72.5%-opaque black styling. Every unchanging label is localized by `TranslateUI` in `FriendListCanvas` or the reusable row prefab; nested layout rebuilds plus a coalesced authoritative refresh queue expose incoming/outgoing pending invitations and accept/decline actions reliably without stale snapshots. The five Font Awesome Quick Access glyphs are centrally aligned on matching 46×46 semi-transparent black slots, and their scene-authored preview titles also use `TranslateUI`. O toggles the panel and Escape closes it. English/Polish actions and LogUI outcomes are localized.
- Strength and Speed potions are server-authoritative consumables and level-1 Alchemy recipes requiring two Chamomile. Their usable-item classes own the `+20` bonus and 60-second duration. A successful use consumes one potion, applies the runtime-only modifier on server and owner, and reusing the same type refreshes rather than stacks it. Strength affects sword damage, Speed affects controller movement, effective totals are shown in Gear UI, and expiry or network teardown clears the modifier without changing persisted base stats. `UIScene` displays active effects in the upper-right as real `InventorySlot` instances with live countdowns and full hover previews. Buff and item views share the same icon loader, while the common item-description builder reads the usable-item constants and displays the exact `Strength: 20` / `Speed: 20` bonus.
- Splitting a stack distinguishes a capacity failure from other invalid input. When the source contains at least two items but no empty/new slot is available, `InventoryUI` displays the localized `InventoryFull` message through `LogUI`; one-item and invalid-slot attempts do not produce a misleading capacity warning.
- Inventory stacks are capped at 1024. Matching partial stacks are filled before overflow is split into new slots, and each inventory update is evaluated atomically against character capacity after removals free any eligible slots. Persisted legacy oversized stacks are normalized without item loss, with empty positions reused before overflow slots are appended and the effective capacity exposed/persisted. A non-fitting command returns `InventoryFull` without persisting partial changes. Unity performs the same complete-command preflight for loot, crafting, merchant, and gear operations; gear swaps validate every returned item including auto-unequipped ammo, cancel before RPC when full, and restore the authoritative character after a server-side rejection. The server persists before synchronizing the owner, and `LogUI` displays the localized full-inventory message. Crafting experience is granted only after a successful inventory update.
- Collect quests now represent current possession rather than historical pickup count. Accepting a Collect quest initializes progress from the selected character's current authoritative inventory; subsequent inventory additions, crafting/usable-item consumption, and merchant sales/removals resynchronize the total. Falling below the requirement reopens Finished to Accepted, and Unity updates the quest log color plus NPC exclamation/question state. Kill progress remains additive. Focused Domain and Infrastructure tests cover absolute synchronization, initial completion, and regression after item loss.
- Crafting now stops without issuing its completion RPC when the player moves, receives actual damage, closes/replaces the crafting panel, presses Escape, or leaves the station radius. The cast bar is reset and the craft button is restored according to the current requirements.
- Player health text now renders `current/max`; current-health and max-health update paths preserve the other value instead of overwriting one shared field.
- The global `ApiExceptionHandler` centrally maps application exceptions to HTTP responses (`InvalidCredentialsException` 401, `ForbiddenAccessException` 403, `ValidationException` 400, `NotFoundException` 404). Authentication endpoints now contain only their success path, and focused tests cover all mappings plus unknown-exception fallthrough.
- `BaseAuditableEntity` and `AuditableEntityInterceptor` centralize `ModDate` updates with a single UTC value per save operation. Quest `StartDate`/`EndDate` also use `TimeProvider.GetUtcNow()`, and the current `20260811172103_Init` baseline creates all application-owned temporal columns directly as `datetimeoffset`. EF Core reports no pending model changes against that snapshot. There are no direct `DateTime.Now`/`UtcNow` calls in application runtime code.
- `POST /api/ApplicationUsers/RefreshSession` accepts either the `Client` or `Server` authorization policy, reloads the bearer-authenticated Identity user and current roles, and issues a unique replacement JWT only during the current token's final five minutes and before the signed 24-hour session deadline; earlier calls receive `403`, while expired/invalid sessions receive `401`. `UserManager` runs an unscaled real-time 56-minute loop, atomically replaces the process-local token, and retries transient failures every 30 seconds only through the remaining four-minute token window. A terminal 4xx, exhausted token window, or 24-hour deadline clears local session state; clients shut down networking/unload authenticated scenes and return to Bootstrap login, while dedicated servers exit. The previous JWT remains accepted until its original expiry, but refreshed client tokens are never sent to the game server.
- Game-session API endpoints register and heartbeat the active dedicated server, issue a random 32-byte base64url ticket valid for 60 seconds, atomically consume it exactly once, issue/revoke a server-only player-session credential, and bind that credential to the authenticated server account. Server leases last 90 seconds; expiry removes all child credentials. Ticket creation is limited to 20 requests per authenticated user per minute (IP fallback before authentication), and a new ticket replaces the previous one for the same client/session. `ServerPlayerSession` authorization resolves the delegated user before gameplay handlers run; the legacy `ClientToken` header and all JWT-bearing RPC parameters are gone.

- `LoadingScene` owns the responsive `LoadingScreen.prefab`, starts the client by loading `BootstrapScene` additively, and stays loaded as the global overlay host. Its Canvas uses full-screen anchors, explicit height-based scaling, sorting order `32000`, and a raycast-blocking dark background.
- `LoadingScreenUI.Instance.Show(message)` returns an idempotent `IDisposable` scope. Overlapping scopes retain the overlay until all are disposed and display every active message in acquisition order, one per line. `LoadingSpinner.prefab` uses `SpinnerUI` with `Time.unscaledDeltaTime` and is shared by the global overlay and the login loading state.

Behind a reverse proxy, load balancer, or CDN it may therefore rate-limit the proxy's shared IP instead of the real client IP. Production deployment must configure and trust forwarded headers before `UseRateLimiter()`; forwarded headers must not be accepted indiscriminately from untrusted senders.
