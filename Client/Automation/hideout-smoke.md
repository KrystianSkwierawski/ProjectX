# Hideout smoke coverage

## Implemented behavior

- Character-private HideoutScene uses DungeonTravel. Farm retains building ID 1 and the existing prefab/meta identities. The entry snapshot now includes every building in the room.
- Initial construction remains 5 Chamomile / 5 seconds. Level 1 has two seed slots; level 2 has four; level 3 has six. Upgrade 1 -> 2 costs 10 Wood + 2 CopperBar / 30 seconds; 2 -> 3 costs 20 Wood + 5 CopperBar / 60 seconds. Costs/times live in Domain FarmState; existing slots keep growing during upgrades.
- Six crops: Chamomile, Strawberry, Mint, Lavender, Calendula, Raspberry. Each has a seed item; the EnvironmentScene merchant offers all six crops and seeds. MerchantNpc prefab has an empty item list; offers belong to the scene instance. Test purchase prices are one coin per item; sale proceeds have a one-coin minimum. The eleven new icons are generated transparent PNGs. The five new gathering prefabs reuse the existing plant mesh with distinct materials and separate registered network prefab identities.
- Seed slots use InventorySlot (maximum 1024). Drag a whole stack into an empty/compatible slot, or right-click inventory seeds to select a fitting slot. Right-click a farm slot, or drag it back into inventory, to withdraw its remaining seeds. Split stacks with the existing inventory Alt-right-click first. A transfer that cannot fit changes neither inventory.
- A planted slot schedules its first crop using its configured spawner RespawnInterval (currently 5 seconds). When due, one seed is consumed and one durable ready crop is recorded. The crop waits for harvest; elapsed offline time does not burn the rest of the stack or accumulate invisible crops. Harvest uses the existing Herbalism cast and atomically grants one product and the server-supplied Herbalism EXP, clears the ready crop and schedules the next seed. Full inventory leaves the crop intact. Withdrawing seeds cancels unfinished growth but leaves an already-ready crop.
- CharacterHideouts.Data is an independent JSON payload selected by building type with Farm state (level, upgrade deadline, revision, six slots with seed InventorySlot, ready product and UTC deadline). The entity stores raw JSON text; Infrastructure provides generic Serialize<T>/Deserialize<T> methods through IHideoutStateSerializer; Application selects the state model using HideoutBuildingEnum. A separate row Revision provides EF concurrency without relying on normalized JSON text. Accepted inventory/Collect/building writes share one commit and the existing trade barrier/quest semaphore; accepted work survives despawn.
- Farm contains six persistent SlotSpawner children at the original crop positions. Level capacity and seed/ready-crop state control activity; the mapped product prefab changes without recreating spawners. A ready crop keeps its spawner active even when no seeds remain. Farm has serialized seed/product/spawner mappings; respawn timings remain on the respective Spawner prefabs. Building visuals follow the shared Content / BuildStation / Countdown convention. Data accepts independent JSON, but operation dispatch, DTO projection and Unity UI remain temporarily Farm-specific. TODO: extract per-type handlers and generalize the API/Unity payload when adding another building type.

- Hideout aligns with the standard left panels and does not change inventory placement. Exit and Build/Upgrade are bottom-left/right; max-level and ongoing construction/upgrade disable the action. Canvas build time appears only before construction; after completion the next upgrade duration is shown. Scene countdown remains unchanged.

## Automated verification

API build/OpenAPI, 537 passing backend tests, SQL Server pending-model check, generated Unity client and UNITY_SERVER compilation, isolated Unity import/Netcode processing, prefab/navigation/construction projections, and rendered UI layouts at 1280x720, 600x1000 and 360x800. Follow-up: all 8 hideout integration tests pass, including requests during construction and during an upgrade using the latest revision. Persistent-spawner editor probes verify all capacities, empty slots, ready crops without seeds and seed-type changes. These editor probes do not establish authenticated gameplay, actual pointer operation, or network timing.
